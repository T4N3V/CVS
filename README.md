# CSV Moodle Log Parser

A small Java command-line example that reads a Moodle activity-log export, maps selected columns to `Person` objects, and writes a plain-text representation to a file.

> **Repository status:** this is an incomplete, non-portable example. The checked-in program does not process the included sample successfully without source changes. See [Current limitations](#current-limitations).

## What the code does

`Main.java`:

1. opens a CSV file with OpenCSV;
2. skips the first row as a header;
3. creates `Person` objects from seven fields;
4. writes each object's `toString()` representation to a text file.

`Person.java` stores these values:

- date;
- full name;
- event context;
- component;
- event name;
- description;
- IP address.

## Technologies

## Setup and attempted use

The source currently contains two owner-specific absolute Windows paths:

```text
C:\Users\og5\IdeaProjects\CVS\src\Logs_moodle.csv
C:\Users\og5\IdeaProjects\CVS\src\records.txt
```

Before attempting to run it, replace those values in `Main.java` with paths available on your machine.

With OpenCSV and its dependencies on the classpath, the source can then be compiled and launched using the standard Java tools. For example, on Windows:

```powershell
javac -cp "path\to\opencsv.jar" Main.java Person.java
java -cp ".;path\to\opencsv.jar" Main
```

On macOS or Linux, use `:` instead of `;` as the classpath separator.

These commands describe the entry point, but a successful conversion of the included sample is not expected until the delimiter issue below is fixed.

## Input and output

The constructor call in `Main.java` expects at least seven fields in this order:

1. date;
2. full name;
3. event context;
4. component;
5. event name;
6. description;
7. IP address.

The intended output is one `Person.toString()` line per parsed object.

Do not treat the checked-in `records.txt` as reproducible output from the current source: its field set and text format differ from the current `Person.java` implementation.

## Current limitations

- `Logs_moodle.csv` is semicolon-delimited, while `new CSVReader(...)` uses OpenCSV's default comma separator. The current code therefore cannot reliably read the included sample.
- Input and output paths are hard-coded to one Windows user directory.
- The inner column loop creates the same `Person` once for every column in a row, producing duplicate output if parsing succeeds.
- The writer and reader are not managed with try-with-resources, and the writer is not explicitly closed.
- Exceptions inside the conversion block are printed and swallowed instead of being reported to the caller.
- There are no automated tests or CI workflow.
- There is no build configuration or dependency lock.
- `records.txt` appears to have been generated by a different revision of the model/output format.
- The application has no command-line options and no graphical interface.

## Data-handling note
